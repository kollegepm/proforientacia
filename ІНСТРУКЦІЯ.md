# Дашборди профорієнтації на Firebase + GitHub Pages

У архіві:

| Файл | Що це |
|---|---|
| `index.html` | Дашборд «Профорієнтація» |
| `tasks.html` | «Тижневі завдання» з календарем |
| `firebase-config.js` | **Єдиний файл, який треба заповнити** |
| `fb.js` | Підключення до Firebase (не змінювати) |
| `firestore.rules` | Правила доступу до бази (вставляються в консоль Firebase) |

Як це працюватиме: сторінки лежать на GitHub Pages, дані — у базі Firestore. Дивитися може будь-хто за посиланням, без входу. Змінювати — лише ви, після входу своїм Google-акаунтом (кнопка «Увійти» вгорі сторінки). Зміни бачать усі одразу, без оновлення сторінки.

---

## Частина 1. Firebase (≈10 хвилин)

1. Відкрийте https://console.firebase.google.com → **Add project** (Створити проєкт). Назва, наприклад, `proforientacia`. Google Analytics можна вимкнути.
2. Ліворуч **Build → Firestore Database → Create database**.
   - Режим: **Production mode**.
   - Розташування: будь-яке європейське (наприклад, `europe-central2` — Варшава). Змінити його потім не можна.
3. У Firestore відкрийте вкладку **Rules**. Видаліть усе, що там є, і вставте вміст файлу `firestore.rules`.
   - У рядку `in ['ваш_email@gmail.com']` впишіть свій Gmail **малими літерами**.
   - Натисніть **Publish**.
4. Ліворуч **Build → Authentication → Get started → Sign-in method → Google** → увімкніть **Enable**, оберіть свій email як support email → **Save**.
5. Натисніть шестерню вгорі ліворуч → **Project settings** → внизу **Your apps** → іконка **`</>`** (Web).
   - Назва застосунку будь-яка, галочку Firebase Hosting **не ставте** → **Register app**.
   - З'явиться блок `const firebaseConfig = { apiKey: ..., ... }`.
6. Відкрийте файл `firebase-config.js` у Блокноті й перенесіть ці значення у відповідні рядки (`apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`). У `owners` впишіть той самий Gmail, що й у правилах. Збережіть файл.

## Частина 2. GitHub Pages (≈5 хвилин)

7. Увійдіть на https://github.com → **New repository**.
   - Назва, наприклад, `proforientacia`, тип **Public** → **Create repository**.
8. На сторінці репозиторію натисніть **uploading an existing file** і перетягніть усі файли з архіву (`index.html`, `tasks.html`, `fb.js`, `firebase-config.js`, можна й решту) → внизу **Commit changes**.
9. **Settings → Pages** → у полі *Source* оберіть **Deploy from a branch**, гілка **main**, папка **/(root)** → **Save**.
   За 1–2 хвилини з'явиться адреса на кшталт `https://ВАШ-ЛОГІН.github.io/proforientacia/`.

## Частина 3. З'єднати й перенести дані

10. Поверніться у Firebase → **Authentication → Settings → Authorized domains → Add domain** → впишіть `ВАШ-ЛОГІН.github.io` (без `https://` і без назви репозиторію) → **Add**.
11. Відкрийте свою адресу GitHub Pages → натисніть **Увійти** → оберіть свій Google-акаунт.
12. Зверху з'явиться плашка **«База ще порожня. Перенести … з попередньої версії?»** → **Перенести**. Так переїдуть записи з дашборда профорієнтації.
13. Перейдіть на «Тижневі завдання» (кнопка біля заголовка) і так само натисніть **Перенести** — переїдуть ваші 12 завдань.

## Посилання для колег

- Профорієнтація: `https://ВАШ-ЛОГІН.github.io/proforientacia/`
- Тижневі завдання: `https://ВАШ-ЛОГІН.github.io/proforientacia/tasks.html`

Колеги бачать усе без входу, але форм і кнопок змін у них немає. Навіть якщо хтось увійде своїм акаунтом, база не дасть йому нічого змінити — це перевіряють правила Firestore, а не сторінка.

## Важливо знати

- **Дані відкриті для читання.** Будь-хто з посиланням бачить записи, тому ПІБ абітурієнтів, телефони та інші особисті дані в примітки не пишіть.
- **Безкоштовно.** Безкоштовного тарифу Firebase (Spark) з великим запасом вистачить на такий обсяг.
- **Дати редагування ще комусь:** додайте його Gmail і в `firestore.rules` (у список в `in [...]`, через кому, малими літерами, потім *Publish*), і в `owners` у `firebase-config.js` (потім завантажте файл на GitHub знову).
- **Якщо щось не працює**, сторінка пише причину вгорі під заголовком:
  - «Firebase ще не налаштовано» — не заповнено `firebase-config.js`;
  - «Цей сайт не додано до дозволених доменів» — пропущено крок 10;
  - «Цей акаунт не має права змінювати дані» — email у правилах або в `owners` не збігається з тим, яким ви увійшли.
